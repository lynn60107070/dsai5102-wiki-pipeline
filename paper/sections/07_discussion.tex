\paragraph{Limitations.} The results come with five limits.
\begin{itemize}
  \item \textbf{One laptop collects.} The stream is read by a single laptop, so sleep, standby and network
    drops opened gaps of up to 16 hours. All were replayed from the feed (\cref{tab:incidents}) and no
    hour of the window is empty, but a collector on a server would not need the replays.
  \item \textbf{15 days of data.} The window, 28 Oct -- 11 Nov 2026, covers two weekly cycles. It shows
    daily and weekly patterns, but not seasons, holidays or rare events such as elections, so the shares
    may differ in another period.
  \item \textbf{Bots are found by their flag.} An edit counts as a bot edit only if its account has the
    bot flag, which each wiki's community grants to approved bots. Bots that run without the flag count as
    humans, and edits a flagged account makes by hand count as bot edits, so the bot share is an estimate.
    Reverts are detected by matching English words such as ``revert'' or ``undo'' in edit summaries, so
    reverts with an empty summary or one in another language are missed.
  \item \textbf{Attention and edits are linked in time, not by cause.} An attention spike followed by an
    edit surge does not show that readers caused the edits: a news event can drive both. A spike also
    needs at least 1{,}000 views in the hour, so smaller articles cannot register one.
  \item \textbf{A single Kafka broker.} Every topic has one copy, which is enough for a laptop but would
    lose buffered events if the broker's disk failed. The lake, not Kafka, is the long-term archive.
\end{itemize}

\paragraph{Possible extensions.}
\begin{itemize}
  \item \textbf{Topics from Wikidata:} link each article to its Wikidata item to ask \emph{which kinds} of
    articles attract bursts of edits, such as people, events or places.
  \item \textbf{Alerting on edit surges:} the per-minute counts per wiki already flow through Kafka, so a
    small consumer could warn patrollers when a wiki's edits jump; alerts per article would need a new
    count by article.
  \item \textbf{Cloud deployment:} run the same containers on a server, with object storage instead of
    MinIO and more Kafka brokers, so collection no longer depends on a laptop staying awake.
\end{itemize}
